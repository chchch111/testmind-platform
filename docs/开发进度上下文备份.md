# RAG思维导图测试用例平台开发进度上下文备份

备份时间：2026-08-07

## 一、项目基本信息

项目名称：基于大模型与RAG的思维导图测试用例自动生成与管理平台

固定技术栈：

- 后端：Python FastAPI
- RAG框架：LangChain
- Embedding模型：BAAI/bge-small-zh-v1.5，运行在应用服务端内部
- 向量数据库：FAISS，文件形式持久化
- 业务数据库：MySQL
- 大模型：DeepSeek-v4-flash 云端 API
- 前端：Vue 3 + Vite + JavaScript + Element Plus + Axios + Vue Router
- 项目形态：前后端分离

重要约束：

- DeepSeek base_url 固定为：https://api.deepseek.com/v1
- DeepSeek model 固定为：deepseek-v4-flash
- API Key 只能从 .env 读取，不能硬编码
- Embedding 和 FAISS 在自有服务端运行，不调用第三方 Embedding API 或第三方向量库 API
- FAISS 文件必须持久化到磁盘，服务重启不能丢失
- bge-small-zh 与 FAISS 可部署在本机或云服务器 CPU 实例，不需要 GPU
- 系统提示词必须禁止输出思考过程、推理草稿和 <reasoning> 标签内容

## 八、重要注意事项

### 新增界面参考要求：思维导图与执行状态交互

用户提供了三张参考图，后续前端必须按这个方向调整：

1. 思维导图不能只用普通 `el-tree`，需要做成类似 XMind 的横向脑图画布。
2. 画布特点：左侧根节点，向右横向展开，多层级蓝色连接线，节点使用圆角矩形或文字节点。
3. 节点中需要支持彩色标签，例如：前置条件、执行步骤、预期结果、主流程、通用、PA20、单端测试等。
4. 深层级内容需要支持横向滚动和纵向滚动，适合展示大用例集。
5. 用例节点需要在同一条链路中呈现：前置条件 → 执行步骤 → 预期结果。
6. 执行端交互需要参考图三：点击用例节点后弹出圆形/浮层状态菜单。
7. 状态菜单包含：通过、失败、阻塞、缺陷、移除、不适用、备注等快捷操作。
8. 执行状态修改要比表格按钮更直观，便于答辩演示“执行端同步任务和更新状态”。

### 其他注意事项

1. 前端第一版不做真实登录，默认用户 ID 为 1。
2. 当前用户 ID 存在 localStorage 中，可在页面右上角修改。
3. DeepSeek API Key 不能出现在前端，只能由后端 `.env` 读取。
4. AI生成和RAG构建索引是耗时操作，前端要显示 loading 和阶段提示。
5. XMind导出必须使用 blob 下载。
6. XMind导入失败必须展示后端错误详情，方便答辩演示异常处理。
7. 版本回退要突出差异对比，这是论文“可追溯性”的可视化支撑。
8. 当前后端没有 CORS 配置，前端开发依赖 Vite 代理。
9. 如果直接用浏览器访问 `http://127.0.0.1:8000/api/...` 没问题；前端页面请求则走 `http://127.0.0.1:5173/api/...`。
