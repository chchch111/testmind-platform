### 8. 2026-08-10 第五批优化（业务闭环）

基于业务梳理完成的 7 项优化：

1. **任务下发固化用例快照**：`test_execution_records` 新增 `case_node_snapshot` JSON 列，任务创建时把每个用例节点内容固化，执行人看到的是下发时的版本，后续编辑不影响执行。
2. **执行人认领任务**：`test_task_assignees.assign_status` 接入 `assigned → accepted` 状态机，新增 `POST /api/tasks/{id}/assign`；执行人必须先认领才能提交执行结果，未认领提交返回 403。认领后任务从 assigned 自动流转到 running。
3. **AI 生成草稿入库**：AI 生成保存的用例集默认 `draft` 状态，新增 `POST /api/case-sets/{id}/publish` 发布为 active；任务创建/知识库导入只允许选择 active 用例集。
4. **任务报告与缺陷汇总**：新增 `GET /api/tasks/{id}/report`，返回通过率、按执行人统计、缺陷清单（failed/blocked 的节点+缺陷描述），TaskDetail 新增"查看报告"。
5. **需求→用例追溯**：`list_case_sets` 对 AI 生成的用例集附带 `generation_id` 和 `requirement_text`，CaseSetList 展示来源需求，实现"需求→知识片段→AI生成→用例集"全链路可追溯。
6. **用例评审闭环**：`case_set_reviews` 新增 `conclusion`、`updated_at`，状态机 `submitted → reviewing → completed`；新增 `PATCH /api/case-sets/{id}/reviews/{rid}`，CaseSetDetail 可"开始评审/完成评审+填结论"。
7. **执行人工作台优先级筛选**：按优先级（P0-P3）筛选、按优先级排序，表格展示优先级标签。

### 9. 2026-08-10 第六批优化（工程与体验）

1. **删除级联清理**：删除用例集时物理清理脑图元数据（标签/备注/链接/图片/评审）、版本快照、评审记录；执行记录展示时标记"已删除"（节点被删后快照仍在但提示已失效）。同时修复删除接口要求 body 导致前端无 body 删除返回 422 的问题。
2. **前端打包优化**：引入 `unplugin-vue-components`/`unplugin-auto-import` 按需引入 Element Plus，路由全部改为懒加载。入口 bundle 从约 1.2MB 降到约 115KB，各页面按需独立 chunk，首屏显著加快。
3. **清理遗留垃圾**：删除 `backend/tmp/` 测试残留、`storage/browser-profile*` 浏览器调试目录、`storage/screenshots/` 调试截图。
4. **文件上传大小限制**：XMind 导入与知识库文件上传校验 `MAX_UPLOAD_MB`（默认 20MB），防止超大文件耗尽磁盘。
5. **用例集 JSON 导出**：新增 `GET /api/case-sets/{id}/export-json`，返回用例集元信息 + 树结构，CaseSetList 增加"导出JSON"按钮。

### 10. 2026-08-10 第七批优化（性能）

1. **用例树接口精简**：`get_case_tree` 改用专用序列化，去掉审计字段（created_by/updated_by/created_at/updated_at），保留渲染与编辑所需字段，大树时降低响应体与解析开销。`CaseNodeTreeOut` 相应精简 schema。
2. **脑图组件性能**：去掉 `JSON.stringify(treeData)` 全量序列化 watch；`emitViewportChange` 用 requestAnimationFrame 节流，滚动/拖拽时全量 DOM 测量一帧内只执行一次，卸载时取消 pending 帧。
3. **AI 保存节点评估**：递归需逐节点 flush 拿父节点 ID，无法消除；几十节点场景收益可忽略，未冒险重构。

### 11. 2026-08-10 第八批优化（执行工作台重构）

按用户需求把执行工作台重构为"任务目录 → 子任务 → 思维导图执行"两级：

1. **任务父子层级**：`test_tasks` 新增 `parent_id`（目录=父任务，子任务=执行单元）和 `owner_id`（负责人）字段，迁移脚本 `backend/sql/02_task_hierarchy.sql`。
2. **任务目录表格**：`ExecutorWork.vue` 重构为 `ExecutorDirectory.vue`，按目录分组展示子任务，列 = 任务ID / 子任务名称 / 目录名称 / 负责人 / 执行人 / 通过率 / 已测用例 / 操作（进入执行）。目录聚合通过率/已测数由后端计算。
3. **子任务思维导图执行页**：新建 `ExecutorTaskDetail.vue`（路由 `executor/tasks/:taskId`），复用 `MindMapCanvas`/`MindNode` 展示用例树 + 点击 case 节点弹 `ExecutionRadialMenu` 标记通过/失败/阻塞/不适用，局部更新状态不整页重载。
4. **思维导图组件扩展**：`MindNode.vue`/`MindMapCanvas.vue` 新增 `nodeExecutionStatusMap` prop，按 node_id 渲染状态徽标（通过绿/失败红/阻塞橙/不适用灰/未执行空心）。
5. **TaskList 两级管理**：测试任务管理改为"创建目录 → 目录下添加子任务（选用例集+执行人）"。
6. **后端接口**：新增 `GET /api/tasks/directories`（目录+聚合统计）、`GET /api/tasks/{parent_id}/subtasks`、`GET /api/tasks/{task_id}/execution-tree`（用例树+当前执行人状态映射合并返回）；`create_task` 支持 `parent_id`/`owner_id`。
