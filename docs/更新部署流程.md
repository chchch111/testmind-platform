# TestMind 项目更新部署流程

记录时间：2026-08-11
适用场景：本地开发改代码 → 同步到云服务器（159.75.202.93:8080）上线

## 一、整体架构

```
本地 Windows（D:/csdn_projects/rag_mindmap_platform）
        │  git push
        ▼
GitHub 私有仓库（chchch111/testmind-platform）
        │  git pull
        ▼
云服务器（/opt/testmind，Ubuntu 22.04）
        ├─ 后端：systemd 服务 testmind，uvicorn 8011
        └─ 前端：Nginx 托管 /opt/testmind/frontend/dist，端口 8080
```

- 本地是**开发源**，所有代码改动在本地完成。
- GitHub 是**中转**，本地 push、服务器 pull。
- 服务器是**运行环境**，只拉取代码，不在服务器上改被 git 追踪的代码。
- 服务器上的 `.env`、数据库、`storage/` 数据、venv 等被 gitignore，`git pull` 不会影响。

## 二、日常更新三步

### 第一步：本地改代码并推送

```bash
cd D:/csdn_projects/rag_mindmap_platform
git add .
git commit -m "本次改动说明"
git push origin main
```

### 第二步：服务器拉取

SSH 登录服务器后：

```bash
cd /opt/testmind && git pull origin main
```

### 第三步：按改动类型让改动生效

| 改动内容 | 需要的操作 |
|---------|-----------|
| 改了前端 Vue 文件 | `cd /opt/testmind/frontend && npm run build` |
| 改了后端 Python 代码 | `sudo systemctl restart testmind` |
| 改了 `.env` 配置 | 手动编辑服务器 `/opt/testmind/backend/.env` 后 `sudo systemctl restart testmind` |
| 数据库加了表/字段 | 执行对应 SQL，必要时重启 testmind |
| 没改代码只改数据 | 无需操作 |

前端 build 和重启后端都不冲突，可以同时做。

## 三、一键更新脚本（可选）

把下面内容存为 `/opt/testmind/deploy.sh`（用 `sudo tee` 创建），以后更新只需 `bash /opt/testmind/deploy.sh`：

```bash
#!/usr/bin/env bash
# TestMind 一键更新：拉取代码 + 重建前端 + 重启后端
set -e
cd /opt/testmind
git pull origin main
cd /opt/testmind/frontend && npm run build
sudo systemctl restart testmind
echo "更新完成！访问 http://159.75.202.93:8080"
```

创建方式：

```bash
sudo tee /opt/testmind/deploy.sh > /dev/null << 'EOF'
#!/usr/bin/env bash
set -e
cd /opt/testmind
git pull origin main
cd /opt/testmind/frontend && npm run build
sudo systemctl restart testmind
echo "更新完成！访问 http://159.75.202.93:8080"
EOF
sudo chmod +x /opt/testmind/deploy.sh
```

## 四、重要约定与注意事项

1. **改代码只在本地**，服务器只负责 `git pull`。若在服务器上直接改被 git 追踪的文件，下次 pull 会被覆盖。
2. `.env`（含 DeepSeek Key、MySQL 密码）在本地和服务器各自维护，**不进 git 仓库**。改 `.env` 要分别改两端。
3. 数据库数据在服务器上，`git pull` 不影响。备份靠 MySQL dump 或整个 storage 目录。
4. 首次部署服务器初始化（建 venv、装依赖、建库）见《云服务器部署过程记录.md》，日常更新不需要重复做。
5. 服务器上不要 `git add`/`git commit`，它只读拉取。若要提交，在本地做。

## 五、常用服务器命令速查

```bash
# 查看后端服务状态
sudo systemctl status testmind

# 查看后端日志（排错）
sudo journalctl -u testmind -n 100

# 重启后端
sudo systemctl restart testmind

# 查看 Nginx 状态
sudo systemctl status nginx

# 数据库登录
mysql -u root -p

# 健康检查
curl -s http://127.0.0.1:8080/health/db
```

## 六、回退方案

如果一次更新引入问题，回退到上一版：

```bash
cd /opt/testmind
git log --oneline -5        # 找到要回退的提交号，如 abc1234
git checkout abc1234 -- backend frontend docs   # 只回退代码文件（不碰 .env/storage/数据库）
# 或彻底回退：
git reset --hard abc1234
cd /opt/testmind/frontend && npm run build
sudo systemctl restart testmind
```

回退只影响代码，`.env`、数据库、storage 数据不受影响。
